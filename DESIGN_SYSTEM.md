# Disco Warp Core — LCARS // Cyberpunk // Minimal

This is the shared visual source of truth for the React inventory application. The October 2026 direction supersedes the previous natural-minimal document. Preserve existing inventory behavior, color provenance and data contracts while making the app feel like a clear, capable starship inventory console.

## Visual hierarchy

- Deep, opaque navy surfaces keep inventory readable. Use amber for the LCARS structural spine, cyan for action and focus, violet for secondary context, and coral for danger. Preserve box/item identity colors as meaningful provenance.
- LCARS character comes from asymmetric corners, slim leading rails, segmented navigation and compact data identifiers. Keep broad glow, nested ornamental frames, idle pulsing and decorative telemetry out of the workspace. The global header has a plain boundary with no LCARS side rail or decorative color bars. Operations view modes use compact SVG card/terminal symbols with accessible labels and hover titles. Operations view toggles and the Actions disclosure share the same raised surface, compact corners, border, typography and soft cyan active fill; they have no individual leading rails. The Operations control console uses an opaque, subtly amber-tinted raised navy background and a slim segmented spectrum bottom rail to separate controls from inventory rows. Each bottom-rail segment has its own multicolor gradient from a coordinated, semi-random hue family chosen once per page load. Rerenders retain the palette. The rail has a subtle 28-second hue cycle, limited to a small shift around its base colors and static under reduced motion. This spectrum treatment is confined to the decorative rail. The console has no left rail; the Items Adrift thumbnail uses a text-free, softly rotating nebula gradient. These scoped ambient accents respect reduced motion and leave entity color provenance unchanged.
- Use the shared sans-serif for human names, controls and prose. Use the data font selectively for box IDs, counts and small section eyebrows. Keep metadata readable, usually at least 0.75rem; avoid walls of tracked uppercase text.
- Retrieval item rows use full-height, center-cropped thumbnails with a slight zoom, simple placement metadata without slash separators, and a large box-color number anchored on the right. The Retrieval box-prefix field uses a gently blinking 000 hint without a BOX label; entered digits remain steady and reduced motion disables the blink. Box Retrieval filters use a collapsible, horizontally scrolling multi-select room carousel sourced from structured room/vicinity/specifics/exactSpot locations. Collapsing preserves room selections; the summary and clear action remain visible. Search sits above the carousel, with tags and sort beneath it. Box Retrieval sort fields use a minimal four-button row (Location, Box ID, Name, Tags) with a separate direction toggle. Retrieval box rows show full-height, center-cropped box photos, or a procedurally projected SVG cube in the box identity colors when a photo is missing or fails. Cube angles vary deterministically by box ID so rerenders do not change them. Retrieval box rows share the same typography, row height, placement hierarchy and right-anchored number; counts use plain text and selected rows retain their identity color.
- Group related content with space and alignment. One boundary per functional panel is enough. Item imagery and useful actions should dominate.

## Source and reuse

`frontend/src/styles/tokens.js` owns palette, geometry, typography and mobile targets. `globalStyles.js` publishes `--dw-*` variables. `styles/primitives.js` exports layout-neutral `controlStyles`, `inputStyles`, `panelStyles` and React primitives `Control`, `Panel`, `Field`, `TextArea`, `StateMessage`.

Use these foundations from Styled Components; do not add Tailwind, TypeScript or a second styling layer. Components retain their own layout and meaningful state colors. The base radius is 8px, control radius 4px, regular control minimum 40px and coarse-pointer target 44px. Clear/dismiss actions keep intrinsic width rather than stretching across a toolbar.

## Inventory color provenance

`frontend/src/util/inventoryColorTheme.js` remains the authoritative mapping. Exactly three digits identify a physical box, including leading zeroes. The first digit selects its family: 0 ice/sky, 1 amber/orange, 2 teal/aqua, 3 lilac/violet, 4 coral/red, 5 lime/green, 6 blue/indigo, 7 magenta/pink, 8 cyan/marine, 9 gold/solar. The remaining digits choose the existing deterministic variant and phase. System collections and Items Adrift retain their neutral palettes.

Apply `getBoxThemeCssVars(getBoxTheme(shortId))` at each entity boundary, including nested boxes and portaled sheets. Entity rails, identifiers and handles use `--box-primary`; location labels retain `--box-location`. Operations box cards carry a translucent gradient from their own primary and secondary colors. Selection brightens that gradient and adds a slow, contained wisp glow behind the content, with a static reduced-motion fallback. Selection must not replace the identity rail with global amber or cyan. Global navigation and workflow framing can use structural amber; keyboard focus remains cyan. Item hues continue to derive from their actual owning box and stable item ID.

## Navigation and responsive behavior

- Design from 320px upward. Let toolbars wrap and lists use available width. Keep essential search, sort and contextual actions visible, with secondary filters in disclosures or sheets.
- Operations search answers use the shared Toast console message channel after a 650ms typing pause. Use a 76px message slot inside the console during search, and smoothly collapse to a 28px quiet idle prompt when the query is cleared. Fade the previous answer out as parameters change, then fade in the settled match; retain the active height while typing; never overlay inventory or expand a result card. Anchor a larger box number on the left, beside three compact lines for item name, box name and horizontally scrollable location. Tint the entire slot with the owning box colors, using its primary rail and secondary box-name and location colors. Fade content in over 220ms without sliding; use a 220ms height transition only when entering or leaving search; disable transitions under reduced motion. A small cycling control handles multiple matches and search parameters control the lifecycle without a dismiss button. Primary system toasts take precedence. Present matched item name, box number, and the recorded location hierarchy. Rank name matches ahead of metadata matches, label the latter as possible matches, and let users step through ambiguous candidates. Keep tags and notes out of this banner; identify unboxed items and missing locations explicitly. Preserve the header Toast confirmations, actions and undo.
- The opaque header occupies normal layout space and exposes its measured height for scroll offsets. First results and focused controls must remain visible below it.
- Operations search result rows and console item names open Quick Peek directly on the matched item. Use a separate small Open item page action for full-page navigation. Keep the Operations query in the URL with replacement while typing so browser Back restores the query and matches without a history entry for every keystroke. Preserve each route, deep link, browser history, query and inventory workflow. Items Adrift opens the Operations Quick Peek slide-up workspace with the same carousel/actions as boxed inventory.
- Operations Quick Peek uses a dark translucent glass surface, softly reflective beveled controls and pressed-state depth. Its header has no leading LCARS rail; previous/next controls use small, thin chevrons on transparent touch targets. On desktop, a directional drop shadow makes the panel clearly float over the inventory. Hide its scrollbar chrome while preserving wheel, touch and keyboard scrolling. Quick Peek keeps the box identity visible in every size. A compact control center offers labelled Items/Notes views, sort, and Open full box. It occupies an opaque bottom layout row within thumb reach on phones, and sits beneath the identity on desktop. Notes share the scrollable content area; controls never cover inventory rows. Active views use a soft wash of the box identity color. Keep text readable, and respect reduced motion.
- Use responsive bounded sheets on tablet/desktop and full-width sheets on phones. Respect safe-area insets, constrain scrolling to sheet bodies and avoid horizontal overflow.

- Location manages the existing Room → Vicinity → Specifics → Exact Spot registry with a Mermaid hierarchy chart. The compact chart flows top to bottom with tightly spaced nodes and fits the available width at its default zoom. It uses cyan rooms, violet vicinities and teal specifics and amber exact spots on opaque navy, with bounded scrolling, a numbered tier legend and cascading branch filters from Room through Exact Spot; its neutral House root is overview context, outside the four specificity tiers. It represents saved containment rather than physical distance or room adjacency; a subtle dot grid supports the cartographic presentation without inventing coordinates. Logs live in the seventh Configuration tab; Location occupies their former main navigation slot.
- Configuration uses a vertical stack of shallow, raised tabs on desktop and a compact two-column stack on phones. Cyan identifies the active tab; opaque surfaces, offset edges and small pressed-state movement provide restrained depth. Render only the active panel, keep batch and staged-file state in a shared controller, and preserve legacy `/import` links alongside `/configuration`.

## Interaction and accessibility

- Visible keyboard focus uses cyan. Use semantic buttons and labels, current/expanded/selected states, readable disabled states, and appropriate live messages.
- Shared dialogs trap keyboard focus, restore it when dismissed, and honor Escape. Nested sheets must not close together or unlock background scrolling prematurely. Keep Back distinct from Close.
- Animate state changes briefly (about 160–260ms). Respect reduced motion globally. Loading and empty/error states should explain what happened and provide a useful next action.
- A Toast is the existing **header-mounted interactive system message**, not an auto-dismiss notification. Preserve its confirmations, actions, undo, persistent status, and explicit dismissal.

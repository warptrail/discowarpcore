# Disco Warp Core — LCARS // Cyberpunk // Minimal

This is the shared visual source of truth for the React inventory application. The October 2026 direction supersedes the previous natural-minimal document. Preserve existing inventory behavior, color provenance and data contracts while making the app feel like a clear, capable starship inventory console.

## Prism Console design language

The preferred focused-workspace expression of LCARS // Cyberpunk // Minimal is **Prism Console**, shortened to **Prism**. The October 13, 2026 Retrieval item Overview reference establishes its character: an opaque navy instrument surface, quietly illuminated by the identity of the thing it holds. This is our working design name. The [design guide](docs/PRISM_CONSOLE_DESIGN_GUIDE.md) explains the reference, aesthetics, vocabulary and application to other surfaces; the [reading edition](docs/prism-console-design-guide.html) includes a small interactive design exercise.

- Give human content priority: bold readable item names, neutral prose, precise monospaced identifiers and quieter supporting facts. Align related content and use space to separate functional groups.
- Use a fine entity-colored shell edge, a static diffused outer halo, faint inset highlights and short corner registration marks on focused sheets. Keep the readable body opaque. These scoped Prism effects refine the general restraint on broad glow and ornamental frames; they do not authorize repeating luminous frames on every field or row.
- Carry the established physical-box palette through entity context and selected tabs. Preserve workflow accents, cyan keyboard focus, semantic feedback and neutral system/Items Adrift palettes. Prism is a language of geometry and hierarchy across colors, rather than a universal blue theme.
- Use the approved Retrieval shell's softer geometry where appropriate: 18px top / 14px bottom corners, 12px photo/placement frames and compact 8–10px secondary groups. Keep shared token defaults and documented route-specific geometry unless the surface is deliberately adapted.
- Translate the principles to each surface's job. Forms use one clear editing workspace; lists use quiet alignment/dividers and restrained selection; navigation uses a legible selected segment. Keep existing information architecture, workflows, mounted drafts, routes and backend contracts. Adapt surfaces incrementally when requested.

## Source and reuse
